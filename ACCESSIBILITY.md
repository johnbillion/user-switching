# User Switching Accessibility Statement

User Switching aims to be fully accessible to all of its users. It implements best practices for web accessibility, outputs semantic and structured markup, adheres to the default styles and accessibility guidelines of WordPress, uses the accessibility APIs provided by WordPress and web browsers where appropriate, and is fully accessible via keyboard.

## Conformance

User Switching should adhere to Web Content Accessibility Guidelines (WCAG) 2.0 at level AA when used with a recent version of WordPress where the admin area itself adheres to these guidelines.

## Supported environments

The plugin adds links and controls to existing WordPress interfaces: the Users screen, user profile screens, the toolbar, the Command Palette, and the login screen. It does not introduce its own UI framework or custom controls. Its accessibility therefore depends largely on the accessibility of the WordPress admin area and of the browser and assistive technology in use.

User Switching supports versions of WordPress up to three years old. Older versions of WordPress may not meet the same accessibility standards as recent versions.

## Known barriers

There are no known accessibility barriers in User Switching at the time of writing. If you find one, please report it.

## Reporting an accessibility issue

If you've experienced or identified an accessibility issue in User Switching, please open a thread in [the User Switching plugin support forum](https://wordpress.org/support/plugin/user-switching/) or [open an issue on GitHub](https://github.com/johnbillion/user-switching/issues) and I'll address it swiftly.
